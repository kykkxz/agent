## 1. Flask 基础

Flask 是 Python 轻量级 Web 框架，核心只有"路由 + 请求上下文"，其他能力（ORM/校验/认证）都靠扩展或自己接。本项目用原生 SQLAlchemy + Pydantic 手动接，让学员看清每个零件。

### 1.1 应用工厂模式

Flask 推荐用**工厂函数**延迟创建 app 实例，方便测试时换配置、生产部署多实例：

```python
def create_app():
    app = Flask(__name__)  # 创建 app
    app.config.from_object(Config)  # 加载配置
    register_blueprints(app)  # 注册路由蓝图
    register_hooks(app)  # 注册钩子
    return app


app = create_app()  # 在启动脚本里调用
```

**为什么用工厂**：直接 `app = Flask(__name__)` 是模块级单例，测试时无法换配置；工厂函数调用才创建，可以生成不同配置的 app（如测试用内存库、生产用 MySQL）。

### 1.2 Blueprint：路由分组

一个项目几十个路由全堆一个文件会乱。Blueprint（蓝图）把路由按业务模块分组，类似"子应用"：

```python
bp = Blueprint("auth", __name__, url_prefix="/api/v1/auth")


@bp.route("/login", methods=["POST"])
def login():
    data = request.get_json()
    ...
```

注册到 app：

```python
app.register_blueprint(bp)  # 实际 url = url_prefix + route = /api/v1/auth/login
```

### 1.3 请求与响应

Flask 路由函数不声明参数类型，靠全局 `request` 对象取数据，返回值用 `jsonify` 转 JSON：

```python
from flask import request, jsonify


@bp.route("/users")
def list_users():
    # 取数据的四种来源
    body = request.get_json()  # JSON body
    file = request.files.get("file")  # 上传文件
    page = request.args.get("page", 1, type=int)  # URL 查询参数 ?page=1
    token = request.headers.get("Authorization")  # 请求头

    return jsonify({"code": 0, "data": [...]})  # 返回 JSON 响应
```

### 1.4 g 对象：请求级全局变量

`g` 是 Flask 的请求级全局对象，**一次请求生命周期内**共享数据，请求结束自动清理。本项目用它挂 DB 会话和当前用户：

```python
@app.before_request
def before_request():
    g.db = SessionLocal()  # 请求开始：建 DB 会话


@app.teardown_request
def teardown_request(exc):
    g.db.close()  # 请求结束：关会话


# 任意路由内通过 g.db 访问
def some_route():
    users = g.db.query(User).all()
```

### 1.5 钩子函数

| 钩子 | 触发时机 | 本项目用途 |
| --- | --- | --- |
| `before_request` | 每次请求前 | （可选）建 DB 会话 |
| `teardown_appcontext` | 请求/上下文结束 | 关 DB 会话 |
| `errorhandler` | 抛异常时 | 统一错误处理 |

### 1.6 路由参数与 methods

```python
# 路径参数：<int:record_id> 自动转 int
@bp.route("/records/<int:record_id>")
def record(record_id): ...

# 多 HTTP 方法
@bp.route("/login", methods=["POST"])   # 只接受 POST
```

## 2. JWT 认证机制

### 2.1 什么是 JWT

JWT（JSON Web Token）是一种紧凑的、URL 安全的令牌格式，用于在客户端和服务器之间安全传输信息。

**JWT 结构** = `Header.Payload.Signature`（三段用 `.` 连接的 Base64 字符串）：

```
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9    ← Header（算法类型）
.eyJzdWIiOiJhZG1pbiIsImV4cCI6MTcwMH0    ← Payload（用户信息+过期时间）
.KikM3v-0hvQQcbol2b91hIYP9CyWX8qR3NzhwqlY8rM    ← Signature（签名防篡改）
```

- **Header**：签名算法（如 HS256）；
- **Payload**：实际数据，常见字段 `sub`（subject，主体）、`exp`（expiration，过期时间）；
- **Signature**：用密钥对前两段签名，防篡改。

### 2.2 认证流程

```
1. 用户登录 → 服务器验证账号密码
2. 服务器生成 JWT（含用户名 + 过期时间），用密钥签名
3. 服务器返回 JWT 给前端
4. 前端存 localStorage，后续请求 Header 携带：Authorization: Bearer <token>
5. 服务器验证签名 + 检查过期 → 提取用户信息 → 处理请求
```

### 2.3 关键概念

| 概念 | 说明 |
| --- | --- |
| `SECRET_KEY` | 签名密钥，只有服务器知道。泄露后 Token 可被伪造，生产必须随机长串 |
| `exp` | 过期时间戳，过期后 Token 自动失效 |
| `sub` | Subject，存用户标识（本项目存用户名） |
| `HS256` | HMAC-SHA256，对称算法（同一密钥签名和验证） |
| 无状态 | 服务器不存 Token，校验只看签名+过期，天然支持水平扩展 |

### 2.4 本项目实现

```python
from jose import jwt


def create_access_token(subject: str) -> str:
    """签发 JWT"""
    expire = datetime.now(timezone.utc) + timedelta(hours=24)
    return jwt.encode(
        {"sub": subject, "exp": expire},  # payload
        settings.JWT_SECRET_KEY,  # 密钥
        algorithm="HS256",
    )


def decode_token(token: str) -> Optional[str]:
    """解析 JWT，返回用户名；失败返回 None"""
    try:
        payload = jwt.decode(token, settings.JWT_SECRET_KEY, algorithms=["HS256"])
        return payload.get("sub")
    except JWTError:
        return None  # 签名错/过期/格式坏都返回 None
```

### 2.5 JWT vs Session

| 对比项 | JWT | Session |
| --- | --- | --- |
| 存储位置 | 客户端（Header） | 服务器端（内存/Redis） |
| 扩展性 | 好（无需共享 Session） | 差（多服务器需共享） |
| 注销 | 难（过期前无法主动失效） | 易（删服务器 Session） |
| 本项目 | ✅ | — |

## 3. RBAC 角色权限控制

### 3.1 什么是 RBAC

RBAC（Role-Based Access Control）= 基于角色的访问控制。核心思想：**不直接给用户授权，而是给角色授权，用户通过角色获得权限**。

```
用户 → 角色 → 权限
admin → 管理员 → 训练模型、导入导出、查看日志
user  → 普通用户 → 预测、生成邮件、编辑 prompt
```

**为什么不直接给用户授权**：用户多、权限组合复杂；角色少且稳定。给角色授权，用户关联角色，管理简单。

### 3.2 本项目角色设计

| 角色 | 可用功能 | 不可用功能 |
| --- | --- | --- |
| admin | 全部 | — |
| user | 数据查看、模型预测、邮件生成、prompt 编辑 | 模型训练、模型导入导出、操作日志 |

### 3.3 装饰器实现 RBAC

本项目用 Python 装饰器实现权限校验，分两层：`login_required`（登录校验）+ `role_required`（角色校验）。

```python
from functools import wraps


def login_required(f):
    """登录校验装饰器：校验 Token + 查用户，通过则放行"""

    @wraps(f)
    def wrapper(*args, **kwargs):
        _authenticate()  # 取 token → 解析 → 查用户 → 挂 g
        return f(*args, **kwargs)

    return wrapper


def role_required(role: str):
    """角色守卫工厂：role_required('admin') 只放行 admin"""

    def decorator(f):
        @wraps(f)
        def wrapper(*args, **kwargs):
            user = _authenticate()  # 先校验登录
            if user.role != role:  # 再校验角色
                raise BizException(1003, "权限不足", 403)
            return f(*args, **kwargs)

        return wrapper

    return decorator
```

**使用**：

```python
@bp.route("/train", methods=["POST"])
@role_required("admin")  # 只有 admin 能访问
def train(): ...


@bp.route("/predict", methods=["POST"])
@login_required  # 登录用户都能访问
def predict(): ...
```

### 3.4 为什么 role_required 是"工厂"

`login_required(f)` 直接接收函数，是普通装饰器。`role_required("admin")` 需要先接收 role 参数再接收函数——写成"外层函数接收 role，返回一个装饰器"，闭包把 role 圈住。这是 Python 装饰器工厂的标准模式。

### 3.5 装饰器执行顺序

```python
@bp.route("/train", methods=["POST"])  # 第3层：注册路由
@role_required("admin")  # 第2层：校验角色
def train_model():  # 第1层：业务逻辑
    ...
```

请求进来时**从外到内**执行：路由匹配 → 角色校验 → 业务逻辑。角色校验不通过直接返回 403，不执行业务逻辑。

## 4. Pydantic 数据校验

### 4.1 为什么用 Pydantic

Flask 没有内置请求体校验，手动校验繁琐易错：

```python
# 原始写法（繁琐、易错）
data = request.get_json()
username = data.get("username")
password = data.get("password")
if not username or not password:
    return jsonify({"message": "参数缺失"}), 400
if not isinstance(username, str):
    return jsonify({"message": "用户名必须是字符串"}), 400
# ... 每个字段都要手动校验
```

**用 Pydantic 后**：声明字段类型，自动校验：

```python
from pydantic import BaseModel


class LoginRequest(BaseModel):
    username: str  # 自动校验是字符串且非空
    password: str


# 路由中使用
data = request.get_json()
try:
    req = LoginRequest(**data)  # 自动校验所有字段
    # 校验通过，直接用 req.username, req.password
except ValidationError as e:
    raise BizException(1001, "参数错误")
```

### 4.2 常用类型注解

| 类型注解 | 含义 | 校验规则 |
| --- | --- | --- |
| `str` | 字符串 | 必须是字符串 |
| `int` | 整数 | 必须是整数 |
| `float` | 浮点数 | 必须是数字 |
| `bool` | 布尔 | 必须 True/False |
| `list[int]` | 整数列表 | 必须是列表且元素都是整数 |
| `Optional[str] = None` | 可选字符串 | 可以是 None 或字符串 |
| `str = "default"` | 带默认值 | 不传时用默认值 |

### 4.3 Field 约束

```python
from pydantic import BaseModel, Field


class RegisterRequest(BaseModel):
    username: str = Field(..., min_length=1, max_length=50)  # 必填，1~50 字符
    password: str = Field(..., min_length=6, max_length=100)  # 必填，至少 6 位
```

`...` 表示必填（Ellipsis），`min_length`/`max_length` 约束长度。

### 4.4 序列化与反序列化

```python
# JSON → Pydantic 对象（反序列化/校验）
req = LoginRequest(**{"username": "admin", "password": "123"})

# Pydantic 对象 → dict（序列化）
data = req.model_dump()  # {"username": "admin", "password": "123"}

# Pydantic 对象 → JSON 字符串
json_str = req.model_dump_json()
```

### 4.5 from_attributes：从 ORM 对象转换

```python
class UserOut(BaseModel):
    id: int
    username: str
    role: str

    class Config:
        from_attributes = True  # 允许从 ORM 对象直接构造


# 直接传 ORM 对象，Pydantic 自动按属性名提取
user_out = UserOut.model_validate(orm_user)
```

这样不用手动 `{"id": u.id, "username": u.username, ...}` 拼 dict。

### 4.6 protected_namespaces 坑

Pydantic v2 默认禁止以 `model_` 开头的字段名（避免与内置方法冲突）。本项目需要 `model_name` 字段，需关闭保护：

```python
class PredictRequest(BaseModel):
    model_config = ConfigDict(protected_namespaces=())
    model_name: Optional[str] = None
```

### 4.7 本项目使用场景

| 场景 | Schema 类 | 用途 |
| --- | --- | --- |
| 登录 | `LoginRequest` | 校验 username/password |
| 注册 | `RegisterRequest` | 校验 username/password |
| 训练 | `TrainRequest` | 校验 models/test_size/params |
| 预测 | `PredictRequest` | 校验 model_name |
| 邮件生成 | `GenerateEmailRequest` | 校验 customer_ids/limit |
| Prompt 更新 | `PromptUpdateRequest` | 校验 content |

## 5. bcrypt 密码加密

### 5.1 为什么不用 MD5/SHA

| 算法 | 安全性 | 问题 |
| --- | --- | --- |
| MD5 | ❌ 不安全 | 可被彩虹表破解，速度太快利于暴力枚举 |
| SHA256 | ⚠️ 不够 | 速度太快，无盐值时仍可被彩虹表破解 |
| bcrypt | ✅ 安全 | 自带盐值 + 可调慢速计算，抗暴力枚举 |

### 5.2 盐值（Salt）

每次哈希时自动生成随机字符串，混入密码一起哈希。**即使两个用户密码相同，哈希值也不同**，防止彩虹表攻击。

### 5.3 bcrypt 工作原理

```
1. 注册：明文密码 → bcrypt.hashpw(密码, bcrypt.gensalt()) → 哈希值（含盐）
2. 登录：用户输入密码 → bcrypt.checkpw(输入密码, 存储的哈希) → True/False
```

`checkpw` 内部从存储的哈希里提取盐，用同一盐重新哈希明文，再比对结果。

### 5.4 本项目实现

```python
from bcrypt import hashpw, gensalt, checkpw


def hash_password(password: str) -> str:
    """密码哈希"""
    pwd_bytes = password.encode("utf-8")[:72]  # bcrypt 最多 72 字节
    return hashpw(pwd_bytes, gensalt()).decode("utf-8")


def verify_password(plain: str, hashed: str) -> bool:
    """校验密码"""
    try:
        return checkpw(plain.encode("utf-8")[:72], hashed.encode("utf-8"))
    except (ValueError, TypeError):
        return False
```

**关键坑**：不用 passlib！passlib 与 bcrypt 4.x 有兼容性 bug（`__about__` 属性丢失），本项目直接用 bcrypt 库。

### 5.5 为什么截断 72 字节

bcrypt 算法只读密码前 72 字节，超长会抛错。统一截断 `[:72]` 让超长密码也能正常哈希校验，不报错。

## 6. SQLAlchemy 2.0 ORM

ORM（Object-Relational Mapping）把数据库表映射成 Python 类，操作对象等于操作数据库，不用写 SQL。

### 6.1 声明式映射（Mapped 类型）

SQLAlchemy 2.0 用 `Mapped` 类型注解，比旧版 `Column` 更清晰：

```python
from sqlalchemy.orm import Mapped, mapped_column
from app.core.database import Base


class User(Base):
    __tablename__ = "users"  # 表名

    id: Mapped[int] = mapped_column(primary_key=True)
    username: Mapped[str] = mapped_column(String(50), unique=True)
    role: Mapped[str] = mapped_column(String(20), default="user")
    created_at: Mapped[datetime] = mapped_column(DateTime, server_default=func.now())
```

**Mapped 的好处**：
- 类型注解让 IDE 自动补全更智能；
- `Mapped[int]` 明确告诉 ORM 字段是整数；
- `Mapped[Optional[str]]` 表示可空字段。

### 6.2 default vs server_default

| 写法 | 时机 | 说明 |
| --- | --- | --- |
| `default="user"` | Python 端 | INSERT 时 Python 填值 |
| `server_default=func.now()` | 数据库端 | DDL 写成 `DEFAULT CURRENT_TIMESTAMP`，由数据库填 |

`created_at` 用 `server_default=func.now()` 更可靠（多服务器时钟不一致时以数据库为准）。

### 6.3 Session 管理

```python
from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker

engine = create_engine("sqlite:///app.db")
SessionLocal = sessionmaker(bind=engine)

# 一次请求一个 Session
db = SessionLocal()
try:
    users = db.query(User).all()
    db.add(User(username="new"))
    db.commit()
finally:
    db.close()
```

本项目在 Flask 里用 `g` 对象管理请求级 Session：请求开始建、请求结束关。

### 6.4 常用查询模式

```python
# 全部查询
users = db.query(User).all()

# 条件查询
admin = db.query(User).filter(User.role == "admin").first()

# 排序 + 分页
page1 = db.query(Customer).order_by(Customer.id.desc()).offset(0).limit(20).all()

# 计数
total = db.query(Customer).count()

# IN 查询
targets = db.query(Customer).filter(Customer.id.in_([1, 2, 3])).all()

# 聚合
from sqlalchemy import func

gender_dist = dict(
    db.query(Customer.gender, func.count(Customer.id)).group_by(Customer.gender).all()
)

# 批量插入（高性能）
db.bulk_insert_mappings(Customer, records)
```

### 6.5 Base.metadata.create_all

```python
Base.metadata.create_all(engine)  # 自动建表
```

扫描所有继承 `Base` 的模型类，在数据库创建对应表。**前提是这些模型类已被 import 过**（否则 ORM 不知道它们存在）。这也是为什么 `app/models/__init__.py` 要把所有模型 import 一遍。

### 6.6 ORM 对象不能直接 JSON 序列化

ORM 对象是 Python 类实例，`jsonify` 不能直接序列化。必须手动转 dict：

```python
def _customer_dict(c: Customer) -> dict:
    return {"id": c.id, "gender": c.gender, "age": c.age, ...}
```

或用 Pydantic 的 `from_attributes=True` 自动转换。

## 7. 大模型调用（LLM）

### 7.1 OpenAI 兼容协议

OpenAI 的 Chat Completions API 已成为行业事实标准。通义千问、DeepSeek、智谱、Kimi 等国产模型都提供"OpenAI 兼容协议"——用 OpenAI 官方 SDK 改个 `base_url` 就能调，换模型不改代码。

```python
from openai import OpenAI

client = OpenAI(
    api_key="your-api-key",
    base_url="https://aigc-api.aitoolcore.com/api/v1",  # 通义千问兼容地址
)
```

### 7.2 消息格式

LLM 接收 `messages` 列表，每条含 `role` 和 `content`：

| role | 含义 |
| --- | --- |
| `system` | 系统设定（角色、风格、约束） |
| `user` | 用户输入 |
| `assistant` | 助手回复（多轮对话时带上历史） |

本项目是单轮对话，只用 `user` 角色：

```python
resp = client.chat.completions.create(
    model="qwen-flash",
    messages=[{"role": "user", "content": prompt}],
    temperature=0.7,
)
content = resp.choices[0].message.content  # 取回复内容
```

### 7.3 关键参数

| 参数 | 说明 | 本项目取值 |
| --- | --- | --- |
| `model` | 模型名 | qwen-flash |
| `messages` | 对话消息列表 | 单条 user |
| `temperature` | 创造力 0~2，越高越发散 | 0.7（文案需要创意但不能崩格式） |

### 7.4 响应结构

```python
resp = client.chat.completions.create(...)
# resp.choices 是列表，取第一条
content = resp.choices[0].message.content
```

### 7.5 降级策略

LLM 是远程服务，可能超时、限流、输出格式错。**必须 try/except 降级**，不让 LLM 故障拖垮业务：

```python
try:
    resp = client.chat.completions.create(...)
    content = resp.choices[0].message.content
    content = re.sub(r"^```json\s*", "", content)  # 清理 markdown 包裹
    return {"success": True, **json.loads(content)}
except Exception as e:
    return {"success": False, "error": str(e)}  # 降级返回失败
```

调用方靠 `success` 字段判断成败，失败照常建记录（status=failed）。

### 7.6 未配置 API Key 的兜底

```python
self.client = OpenAI(...) if settings.LLM_API_KEY else None
# 没配 key 时 client=None，系统照常跑，只是邮件功能不可用
```

## 8. Prompt 工程

Prompt（提示词）是给 LLM 的输入指令。Prompt 工程是设计 Prompt 让 LLM 稳定输出符合预期结果的技巧。

### 8.1 Prompt 四要素

一个工程化 Prompt 通常包含四部分：

| 要素 | 作用 | 本项目示例 |
| --- | --- | --- |
| 角色设定 | 告诉 LLM 它是谁，影响语气和专业度 | "你是保险营销文案专家" |
| 上下文/画像 | 提供任务所需的背景信息 | "客户画像：性别{gender}，年龄{age}岁..." |
| 任务要求 | 明确要做什么、怎么做 | "生成一封个性化车险营销邮件，语气专业有温度，含 CTA" |
| 输出格式 | 约束输出结构，便于程序解析 | "仅返回严格 JSON，格式：{subject, content}" |

### 8.2 本项目默认 Prompt

```
你是保险营销文案专家。请根据以下客户画像生成一封个性化车险营销邮件。
客户画像：性别{gender}，年龄{age}岁，{driving_license}驾照，车龄{vehicle_age}，车辆{vehicle_damage}，年保费{annual_premium}元。
要求：语气专业有温度，突出该客户画像的痛点与利益，包含行动号召(CTA)。
仅返回严格 JSON，格式：{"subject":"邮件主题","content":"HTML格式正文"}
```

### 8.3 占位符与 str.format

Prompt 模板用 `{gender}` 命名占位符，运行时用 `str.format` 填充：

```python
template = "客户画像：性别{gender}，年龄{age}岁"
prompt = template.format(gender="男", age=44)
# → "客户画像：性别男，年龄44岁"
```

**为什么不用 f-string**：f-string 是代码期拼接（`f"...{gender}..."` 写死在代码里）。本项目的模板从数据库读（运营可在线编辑），运行时是字符串，必须用 `str.format`。

### 8.4 花括号转义

`str.format` 把 `{xxx}` 当占位符。如果 Prompt 里要保留字面花括号（如 JSON 格式示例 `{"subject":"..."}`），必须用 `{{` `}}` 转义：

```python
template = '格式：{{"subject":"邮件主题"}}'  # 写两个 {{
prompt = template.format(...)
# → '格式：{"subject":"邮件主题"}'           # 输出一个 {
```

### 8.5 严格 JSON 输出

要求 LLM "仅返回严格 JSON"，下游才能 `json.loads` 解析。但 LLM 有时会包裹 markdown 代码块：

```
```json
{"subject":"...", "content":"..."}
```
```

需要正则清理：

```python
content = re.sub(r'^```json\s*', '', content)   # 去开头 ```json
content = re.sub(r'\s*```$', '', content)       # 去结尾 ```
result = json.loads(content)
```

### 8.6 反编码：ML → LLM 的桥梁

ML 用 0/1 编码训练，LLM 看自然语言。两者衔接处必须把编码值反解为人类语言：

```python
# ML 编码（喂给模型）
driving_license: 1
vehicle_damage: "Yes"

# 反编码（喂给 LLM）
driving_license = "有" if customer["driving_license"] == 1 else "无"
vehicle_damage = "曾受损" if customer["vehicle_damage"] == "Yes" else "未受损"
```

LLM 不懂 0/1，必须转成"有驾照"/"曾受损"才能理解客户画像。

### 8.7 Prompt 模板管理

Prompt 不写死代码，存入 `prompt_templates` 表，运营在前端改文案不用重新部署：

```python
tpl = db.query(PromptTemplate).filter(PromptTemplate.is_active == True).first()
prompt_template = tpl.content if tpl else DEFAULT_PROMPT_TEMPLATE
```

`is_active=True` 标记当前生效模板，启动时 seed 一份默认模板兜底。

## 9. RESTful API 设计规范

REST（Representational State Transfer）是 Web API 的主流设计风格，核心是"资源 + HTTP 方法"。

### 9.1 HTTP 方法语义

| 方法 | 语义 | 本项目示例 |
| --- | --- | --- |
| GET | 查询资源 | `GET /api/v1/data/customers` |
| POST | 创建/触发动作 | `POST /api/v1/auth/login`（登录） |
| PUT | 整体更新 | `PUT /api/v1/email/prompt`（更新模板） |
| PATCH | 部分更新 | `PATCH /api/v1/email/records/1`（标记状态） |
| DELETE | 删除 | `DELETE /api/v1/email/records/1` |

### 9.2 URL 设计

```
/api/v1/auth/login            ← 版本号 + 模块 + 动作
/api/v1/data/customers        ← 复数名词表示资源集合
/api/v1/data/customers/123    ← 路径参数表示单个资源
/api/v1/model/export/xgboost  ← 动作型 URL
```

**约定**：
- 用名词不用动词（动作由 HTTP 方法表达）；
- 资源集合用复数（customers）；
- 路径参数标识单个资源（/records/123）。

### 9.3 状态码

| 状态码 | 含义 | 本项目场景 |
| --- | --- | --- |
| 200 | 成功 | 正常返回 |
| 400 | 客户端请求错误 | 参数缺失、资源不存在 |
| 401 | 未认证 | 未登录或 Token 过期 |
| 403 | 无权限 | 普通用户访问 admin 接口 |
| 500 | 服务器错误 | 代码异常 |

### 9.4 统一响应格式

```json
{
  "code": 0,        // 业务码：0=成功，非0=业务错误
  "data": { ... },  // 业务数据
  "message": "..."  // 提示信息
}
```

**为什么 HTTP 200 也可能表示失败**：有些业务错误（如"无数据，请先上传"）不是 HTTP 层面问题，但需告诉前端操作有误。HTTP 状态码表示传输层状态，`code` 表示业务层状态。本项目两者结合：HTTP 4xx/5xx + 业务 code。

### 9.5 分页响应

```json
{
  "code": 0,
  "data": {
    "items": [ ... ],
    "total": 1110,
    "page": 1,
    "per_page": 20,
    "pages": 56
  }
}
```

## 10. pydantic-settings 配置管理

### 10.1 为什么用 pydantic-settings

传统配置管理用 `.py` 文件或 `app.config` 字典，缺点是无类型校验、容易拼错 key。`pydantic-settings` 把配置声明成类属性，自动从 `.env` 读取并做类型校验。

### 10.2 用法

```python
from pydantic_settings import BaseSettings, SettingsConfigDict


class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_file=".env", extra="ignore")

    APP_NAME: str = "保险精准营销系统"
    DATABASE_URL: str = "sqlite:///./instance/insurance.db"
    JWT_SECRET_KEY: str = "jwt-secret-change-me"
    JWT_ACCESS_TOKEN_EXPIRE_MINUTES: int = 1440
    LLM_API_KEY: str = ""


settings = Settings()  # 模块级实例化，全局复用
```

### 10.3 工作机制

1. 声明字段类型 + 默认值（无 `.env` 时用默认值兜底）；
2. `model_config` 指定从 `.env` 读取，覆盖默认值；
3. `extra="ignore"` 忽略 `.env` 中多余的变量；
4. 模块底部 `settings = Settings()` 一导入就实例化，全局 `from app.core.config import settings` 使用。

### 10.4 类型校验价值

```env
# .env 写错类型
JWT_ACCESS_TOKEN_EXPIRE_MINUTES=abc
```

pydantic-settings 启动时直接报错，而不是悄悄变成字符串导致后续计算崩溃。这是类型校验的核心价值——**早失败、早发现**。

### 10.5 本项目配置项

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| DATABASE_URL | sqlite:///./instance/insurance.db | 数据库连接 |
| JWT_SECRET_KEY | jwt-secret-change-me | JWT 签名密钥（生产必改） |
| JWT_ACCESS_TOKEN_EXPIRE_MINUTES | 1440 | Token 有效期（分钟） |
| LLM_API_KEY | （空） | 大模型 API Key |
