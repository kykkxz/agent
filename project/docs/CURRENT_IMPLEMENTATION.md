# 蜀道安全助手当前实现基线

> 更新时间：2026-08-14
> 依据：当前 `frontend/`、`backend/`、`database/` 可运行代码反向整理。
> 用途：本文件描述当前版本已经实现的行为；专题文档中超出本文件的内容均视为目标方案或后续规划。

## 1. 产品入口与布局

- 登录后默认进入 `/`，核心页面为 AI 安全助手。
- 全局功能入口使用顶部横向导航，不占用页面左侧整列。
- 移动端将顶部导航折叠为菜单，业务内容保持单列。
- AI 会话历史、隐患台账、考试任务记录属于页面内部工作区，可保留左侧记录栏；它们不是全局导航。
- 当前视觉规范沿用原项目的深墨绿背景、米白文字、琥珀主操作色与宋体标题。

## 2. 前端路由

| 路由 | 页面 | 角色限制 |
| --- | --- | --- |
| `/` | AI 安全助手 | 已登录用户 |
| `/hazards` | 隐患提示与图片智能批注 | 已登录用户 |
| `/hazards/create` | 上报隐患 | 已登录用户 |
| `/hazards/:id` | 隐患详情与闭环操作 | 已登录用户 |
| `/exams` | 考试工坊 | 已登录用户；管理操作由接口继续校验 |
| `/exams/take/:paperId` | 在线考试 | 已登录用户 |
| `/exams/result/:attemptId` | 考试结果 | 已登录用户 |
| `/knowledge` | 只读知识库 | `Admin`、`SafetyOfficer` |
| `/overview` | 态势总览 | 已登录用户 |
| `/questions` | 题库审核 | `Admin`、`SafetyOfficer` |
| `/users` | 人员权限 | `Admin` |

`/ai` 兼容重定向到 `/`。未登录访问业务路由时跳转到 `/login`；无权访问受限路由时返回 AI 助手。每次路由切换后页面统一回到顶部，避免从长列表进入详情时继承旧滚动位置。

## 3. AI 安全助手

当前问答链路：

```text
用户问题 -> 查询只读交通安全知识库 -> 取得最多 5 条正式依据
       -> 已配置模型时调用 LangChain create_agent
       -> Agent 必须调用 search_safety_documents 工具
       -> 返回带 [1]、[2] 编号的回答和结构化 citations
       -> 未配置模型或模型失败时返回证据拼接答案
```

- 模型由项目根目录 `.env` 中的 `LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL` 配置。
- 对话按用户隔离，支持创建、列表、读取、重命名和删除会话。
- 前端当前使用同步接口 `POST /api/v1/ai/chat/sync`；后端同时保留 `POST /api/v1/ai/chat` 的 SSE 响应形式。
- 每条助手消息持久化引用信息，前端在右侧证据栏显示标题、片段、发布机构和权威等级。
- 未配置远程模型时仍可使用本地知识库证据模式，不对外发起模型请求。

## 4. 隐患提示与图片批注

- `/hazards` 同时呈现隐患台账、现场图片工作区和分析报告。
- 图片分析接口为 `POST /api/v1/hazard-analysis/analyze`，上传格式支持 JPG、PNG、WEBP，大小上限 15 MB。
- 视觉模型配置优先读取 `VISION_API_KEY`、`VISION_BASE_URL`、`VISION_MODEL`，未单独配置时复用 LLM 配置。
- 后端通过 `backend/app/services/hazard_annotation.py` 解析视觉模型结果并绘制批注；`backend/scripts/annotate_hazards.py` 提供独立命令行入口。
- 隐患识别提示词位于 `backend/app/prompts/hazard_detection.txt`，API 与命令行入口复用同一份内容。
- 批注图与 JSON 结果写入业务上传目录，不写入知识库。
- 一次图片分析汇总创建一条待派单隐患记录，自动关联原图与批注图；未识别到隐患时不创建空记录。
- 隐患详情页提供“返回隐患台账”操作，返回后可继续选择其他隐患。
- AI 与视觉模型请求默认等待上限为 300 秒，可通过 `AI_REQUEST_TIMEOUT_SECONDS` 调整。

## 5. 考试工坊

- 管理员和安全员可按知识点、题型和数量生成待审核题目。
- 当前 `POST /api/v1/exam/ai/generate` 使用只读知识库片段作为解析依据，并以确定性模板生成题目；尚未调用远程大模型生成题干。
- 支持题库审核、试卷创建与发布、员工开考、提交答案和查看成绩。
- 页面布局参考 `考试工坊.png`：任务记录、组卷配置和实时预览在同一工作区。
- 管理员和安全员可点击历史组卷任务切换当前试卷；草稿可恢复编辑并保存，已发布试卷可直接进入考试。
- 题库审核以“待审核队列 -> 当前题目 -> 答案依据 -> 通过或驳回”为主流程，并通过顶部模式切换进入手工录题。

## 6. 知识库与数据边界

- 业务库：`backend/data/app.db`，保存用户、隐患、考试、会话、消息和通知等可写数据。
- 知识库：`database/transport-safety-kb/data/transport_safety_kb.sqlite3`，以 SQLite 只读 URI 和 `PRAGMA query_only=ON` 打开。
- 检索范围限定为未失效、已通过校验、位于正式依据层的知识条目。
- `/knowledge` 当前提供概览、文档分页和关键词检索，不提供前端上传、编辑或删除。
- Chroma 路径可配置，但当前在线检索实际使用 `transport_kb.search` 对已加载正式条目执行本地检索；旧文档中的完整混合检索、RRF 和 CrossEncoder 属于目标方案。

## 7. 当前实现与目标方案边界

以下能力在旧文档中有设计描述，但当前代码尚未完整实现，不能按已交付能力对外声明：多厂商模型路由和自动故障切换、完整 BM25 + 向量 + RRF + CrossEncoder 链路、前端逐 Token 流式渲染和停止生成、知识库上传解析与增量向量化、远程 LLM 结构化出题、Redis 与生产级高并发指标。

后续实现上述能力时，应先更新代码与测试，再同步修改本基线文件及对应专题文档。
