# 交通建设与运营安全

## 第一轮数据采集插件规划

### 1. 方案定位

建设“交通建设与运营安全外部知识源池”，为 AI 对话、事故案例检索、安全培训和风险问答提供权威、可追溯、可引用的外部知识。

第一轮核心知识范围：

1. 安全生产法
2. 建设工程安全生产管理条例
3. 企业安全管理制度
4. 安全操作规程
5. 应急预案
6. 典型事故案例分析

本项目不是泛交通资讯采集系统，重点是法规标准、监管要求、企业安全文件、事故调查材料、应急处置资料和专业研究成果。

### 2. 总体架构

采用“来源插件适配、统一格式处理、集中治理、分级发布”的架构。插件只负责发现、抓取和初步解析，不直接决定内容是否可信，也不直接把内容写入正式知识库。

```text
来源采集插件
    -> 原始资料区
    -> 网页/PDF/扫描件解析
    -> 文档分类与元数据抽取
    -> 去重与版本管理
    -> 合规准入与质量评估
    -> 证据单元切分
    -> 人工审核
    -> 正式依据层/专业参考层/待核验层
    -> 检索与培训应用
```

#### 内容分层

- **正式依据层**：现行有效法律法规、正式监管要求、有效企业制度、已批准规程和预案、官方事故调查报告。
- **专业参考层**：合法获取的论文、技术报告、行业资料和经审核的事故分析。
- **待核验层**：论坛帖子、来源不明转载、版本不清或证据不足的资料。

待核验层不得直接生成强制性安全要求。

### 4. 各插件采集范围

#### 4.1 法规采集插件

首轮采集：

- 现行有效的《中华人民共和国安全生产法》
- 现行有效的《建设工程安全生产管理条例》
- 官方修订说明、实施解读和配套文件
- 与交通建设、桥梁、隧道、道路运营、施工单位相关的条款

必须保留发布机关、文号、发布日期、生效日期、修订关系、废止状态、条款定位和原文链接。已废止版本可保留用于历史查询，但不能作为现行安全要求发布。

#### 4.2 监管文件插件

重点采集：

- 交通运输、铁路、民航、海事、应急、住建监管要求
- 安全检查通知和隐患整改要求
- 专项整治、风险分级管控和应急管理文件
- 监管处罚及事故整改通报

地方文件必须标明行政层级、适用地区和适用范围，不能与国家法规混为一谈。

#### 4.3 事故案例插件

首轮优先采集近 5—10 年官方材料，覆盖坍塌、起重、高处、触电、机械伤害、隧道火灾、桥梁事故、道路碰撞、轨道交通运营、港口船舶、危化品运输、极端天气和地质灾害等。

每起事故拆分为：

```text
事故经过
直接原因
间接原因
责任认定
监管问题
整改措施
官方来源
```

同一事故的新闻、调查报告和整改通报应建立关联，不能重复计数。

#### 4.4 企业制度插件

首轮覆盖 20—30 家具有代表性的交通建设和运营企业或项目，重点采集安全生产责任制、风险分级管控、隐患排查治理、分包和承包商管理、特种作业人员管理、设备设施管理、安全教育培训、事故报告和责任追究制度。

企业制度只能标记为“企业适用要求”，不能自动升级为国家通用法规。

#### 4.5 操作规程插件

首轮先覆盖 10—15 个高风险场景：

- 高处作业、起重吊装、有限空间、临时用电、动火作业
- 爆破作业、深基坑、脚手架、隧道施工、桥梁施工
- 道路养护、隧道运营和应急抢修

每份规程必须绑定适用岗位、设备、作业条件和企业范围，不能把不同企业规程直接合并。

#### 4.6 应急预案插件

重点采集综合应急预案、施工现场专项预案、隧道火灾预案、道路交通事故预案、危化品运输事故预案、极端天气和地质灾害预案，以及人员伤害、坍塌、火灾等现场处置方案。

预案正文、演练方案和演练复盘应分开存储，避免把演练设想当成正式处置要求。

#### 4.7 专业期刊插件

仅采集公开或已获授权的论文和技术报告，记录作者和机构、期刊卷期页码、DOI 或原文编号、研究对象、样本范围、结论适用边界、撤稿和勘误信息。

论文结论只能作为专业参考，不能直接转化为企业强制制度。

#### 4.8 安全论坛插件

仅采集行业协会和学会论坛、专业会议资料、实名专家或工程师经验、事故复盘和风险讨论。

论坛内容必须区分事实、观点、经验和未经验证建议。匿名帖子只能作为线索，不能直接进入正式知识库。

### 5. 插件统一接口职责

每个来源插件建议实现：

```text
discover()  发现新增或更新的文档
fetch()     获取网页、附件或 API 内容
extract()   提取正文、附件和基础元数据
normalize() 转换为统一文档结构
emit()      输出标准文档事件
```

插件内部可以使用网页、API、文件目录等不同方式，但不能把来源特有字段直接暴露给下游治理模块。

统一运行约束：

- 插件可独立启停、升级和回滚
- 新增来源插件不修改核心治理模块
- 单个来源失败不影响其他插件
- 支持增量采集、失败重试和失败清单导出
- 每个采集任务具备唯一任务编号

### 6. 统一数据结构

所有插件至少输出：

```text
document_id
source_id
source_uri
title
publisher
document_type
published_at
effective_from
effective_to
version_status
jurisdiction
applicable_role
applicable_activity
authority_level
license_status
content_hash
retrieved_at
section_locator
review_status
```

关键字段说明：

| 字段 | 说明 |
|---|---|
| `document_id` | 系统内部稳定标识 |
| `source_uri` | 原始 URL、文件路径或文档编号 |
| `document_type` | 法律、条例、制度、规程、预案、调查报告、论文、帖子等 |
| `version_status` | 当前有效、历史有效、已废止、待确认 |
| `jurisdiction` | 国家、省、市、企业或项目范围 |
| `authority_level` | 权威等级和使用限制 |
| `license_status` | 公开许可、已授权、订阅、未知等 |
| `content_hash` | 规范化正文指纹 |
| `section_locator` | 条款、章节、页码、段落或 DOM 定位 |
| `review_status` | 未审、机器初审、人工通过、驳回、隔离 |

### 7. 原始资料、证据和知识条目

#### 7.1 原始资料

保存网页、文件、附件、原始 URL、采集时间、格式、文件哈希和下载记录。原始资料只读保存，不用清洗结果覆盖。

#### 7.2 标准文档

保存统一标题、发布机构、日期、版本、生效状态、章节结构、正文、附件关系和适用范围。

#### 7.3 证据单元

切分为可引用的最小单元，包括法律条款、制度章节、操作步骤、预案处置环节、事故报告事实段落、论文研究结论和论坛具体发言。证据单元必须保留原文位置。

#### 7.4 知识条目

知识条目用于检索和问答，至少包含主题、风险类别、适用对象、内容结论、来源等级、引用列表、审核状态和失效状态。知识条目不能替代原始证据。

### 8. 版本与去重

采用“来源版本、内容版本、关系版本”三层管理：

- 来源版本：修订号、文号、版本号、生效日期和废止日期
- 内容版本：规范化正文、附件和结构哈希
- 关系版本：修订、替代、废止、解释、引用、拆分和合并

去重采用精确去重、近似去重和语义审查三层策略。法规部分修订、项目专用制度、设备型号差异和新增调查结论不得自动合并。

法规新版本发布后，旧版本不物理删除，保留历史状态和审计记录。

### 9. 准入和硬拦截规则

#### 必须满足

- 来源身份可以验证
- 采集方式符合网站条款、授权和许可证要求
- 内容与交通建设或运营安全直接相关
- 标题、发布机构、日期、版本或来源链接基本完整
- 正文和附件完整性可判断
- 文档可回溯到原始位置

#### 直接拦截或隔离

- 绕过登录、验证码或访问控制获取的内容
- 违反合同、数据库许可或网站明确禁止采集的内容
- 来源身份无法确认或疑似伪造的文档
- 恶意脚本、宏文件、可执行附件或疑似恶意链接
- 伪造法规、伪造事故报告或疑似篡改原文
- 关键条款 OCR 错误且无法人工复核的扫描件
- 未脱敏的身份证号、手机号、住址等个人信息
- 企业账号、口令、密钥、网络拓扑和未公开漏洞信息
- 由论坛观点直接推导出的强制性安全要求

#### 来源分级

| 等级 | 内容 | 用途 |
|---|---|---|
| A | 正式法规、政府事故调查报告、有效企业制度 | 可进入正式依据层 |
| B | 正式期刊论文、行业协会标准、权威技术报告 | 审核后进入专业参考层 |
| C | 实名专家或工程师论坛经验 | 仅作为经验和线索 |
| D | 匿名帖子、营销软文、来源不明转载 | 默认隔离或拒收 |

### 10. 首轮 MVP 指标

#### 内容覆盖

- 2 部核心法规全文，版本、日期、状态和来源链接完整率 100%
- 20—30 家企业或项目制度
- 10 个以上高风险操作场景
- 20 份以上应急预案
- 50 起以上典型事故案例
- 官方事故调查报告占案例总量不低于 70%

#### 数据质量

- 可访问原文或稳定引用链接比例不低于 95%
- 文档解析成功率不低于 95%
- 重复文档率不高于 5%
- 关键字段抽取准确率不低于 90%
- 正式法规条款结构完整率 100%
- 正式知识条目引用完整率不低于 95%

#### 检索验收

准备不少于 30 个固定测试问题，覆盖法规条款定位、责任主体查询、作业风险与控制措施、应急响应流程、事故原因与整改措施、同类制度或规程对比。

目标指标：

- 相关文档 Top 5 命中率不低于 85%
- 法规类问题原文条款命中率不低于 90%
- 回答来源完整率不低于 95%
- 知识库未覆盖的问题明确返回“未收录”或“缺少依据”

### 11. 首轮不纳入范围

- 与交通建设和运营安全无关的泛交通新闻
- 未标明来源、发布单位或版本的转载
- 匿名论坛、营销文章和无法核验的经验
- 未经授权的付费论文和数据库批量下载
- 绕过登录、验证码或访问限制获得的内容
- 未脱敏的事故人员隐私信息
- 企业内部未公开或涉及敏感信息的制度和预案
- 实时视频、传感器、工单和人员定位数据
- 自动替企业编制或修改正式制度、规程和应急预案

### 12. 推荐实施顺序

#### 第一阶段：权威依据基线

实现法规采集、监管文件和来源治理插件，完成两部核心法规和监管文件的版本、引用、去重与准入闭环。

#### 第二阶段：案例和可执行内容

实现事故案例、企业制度、操作规程和应急预案插件，补齐事故复盘、岗位操作和现场应急内容。

#### 第三阶段：专业参考扩充

实现专业期刊和安全论坛插件，建立专业参考层和待核验层，确保低权威内容不会直接进入正式依据层。

### 13. 交付物

第一轮应形成：

1. 外部数据源白名单和来源登记表
2. 采集插件接口约定
3. 六类核心知识的分类标签和字段规范
4. 原始资料、标准文档、证据单元和知识条目数据模型
5. 合规准入、版本、去重和引用追踪规则
6. 三层知识发布规则
7. 首轮采集任务清单和失败重试清单
8. 30 个固定检索测试问题及验收报告
