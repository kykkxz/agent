## 模块二：MVC架构

### 1.为什么要分层？

```python
# 反例：全部堆在一个文件（千万别这么干）
from flask import Flask, request, jsonify
import sqlite3, bcrypt, jwt

app = Flask(__name__)

@app.route("/login", methods=["POST"])
def login():
    data = request.get_json()                    # 取参数
    conn = sqlite3.connect("db.sqlite")          # 连数据库
    user = conn.execute("SELECT * FROM users WHERE username=?", (data["username"],)).fetchone()  # 查用户
    if not user or not bcrypt.checkpw(data["password"].encode(), user[2]):  # 验密码
        return jsonify({"code": 1002, "message": "用户名或密码错误"}), 401
    token = jwt.encode({"sub": user[1]}, "secret", algorithm="HS256")  # 签 token
    return jsonify({"code": 0, "data": {"access_token": token}})       # 返回
```

这段代码有哪些问题：

- 数据库连接，SQL操作，密码校验，JWT，响应格式，都在一个函数里

- 可扩展性和可维护性

- 可扩展性：更换数据库，你都找不到地方，sqlalchemy替代

- 可扩展性：改变一个加密方式，每个接口都要改一边

- 多人协作时，不同人员改不同模块，无法操作
  
  

**分层的核心思想**：解耦，把不不同职责的代码放到不同的文件夹（层）里，每层只管自己的事，层与层之间通过函数调用来进行沟通和数据传递



### 2.MVC 分层

 是一种经典的分层方式，三个字母代表三层：

| 字母    | 全称         | 中文   | 干什么                      | 本项目对应                           |
| ----- | ---------- | ---- | ------------------------ | ------------------------------- |
| **M** | Model      | 模型层  | 管数据（数据库表、增删改查）           | `app/models/`                   |
| **V** | View       | 视图层  | 管展示（Web 里就是返回给前端的响应）     | `app/core/response.py` + 路由里的返回 |
| **C** | Controller | 控制器层 | 管编排（接收请求、调 Model、调 View） | `app/api/v1/`                   |

* * *



| 步骤  | 谁 → 谁                                   | 方式                       |
| --- | --------------------------------------- | ------------------------ |
| 1   | **View → Controller**                   | 浏览器发 HTTP 请求（fetch/ajax） |

### 2. JWT ：

用于在客户端和服务器之间安全传输信息

```
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9    ← Header（算法类型）
.eyJzdWIiOiJhZG1pbiIsImV4cCI6MTcwMH0    ← Payload（用户信息+过期时间）
.KikM3v-0hvQQcbol2b91hIYP9CyWX8qR3NzhwqlY8rM    ← Signature（签名防篡改）
```

认证流程
    1. 用户登录 → 服务器验证账号密码
    2. 服务器生成 JWT（含用户名 + 过期时间），用密钥签名
    3. 服务器返回 JWT 给前端
    4. 前端存 localStorage，后续请求 Header 携带：Authorization: Bearer <token>
    5. 服务器验证签名 + 检查过期 → 提取用户信息 → 处理请求



session：服务器在存相应的通关信息

JWT：浏览器和客户端自己存的通关信息

为什么要这么做？发送请求超载，分发请求到别的服务，避免重复存储和重复验证

| 对比项  | JWT             | Session         |
| ---- | --------------- | --------------- |
| 存储位置 | 客户端（Header）     | 服务器端（内存/Redis）  |
| 扩展性  | 好（无需共享 Session） | 差（多服务器需共享）      |
| 注销   | 难（过期前无法主动失效）    | 易（删服务器 Session） |
| 本项目  | ✅               | —               |

### 3. RBAC角色权限控制

role-based access control ，基于角色的访问控制，核心思想：不直接给用户授权，而是给角色授权，用户通过角色的判定来获取权限

```
用户 → 角色 → 权限
admin → 管理员 → 训练模型、导入导出、查看日志
user  → 普通用户 → 预测、生成邮件、编辑 prompt
```

通过装饰器来进行角色权限控制

```python
from functools import wraps

def login_required(f):
    """登录校验装饰器：校验 Token + 查用户，通过则放行"""
    @wraps(f)
    def wrapper(*args, **kwargs):
        _authenticate()          # 取 token → 解析 → 查用户 → 挂 g
        return f(*args, **kwargs)
    return wrapper

def role_required(role: str):
    """角色守卫工厂：role_required('admin') 只放行 admin"""
    def decorator(f):
        @wraps(f)
        def wrapper(*args, **kwargs):
            user = _authenticate()       # 先校验登录
            if user.role != role:        # 再校验角色
                raise BizException(1003, "权限不足", 403)
            return f(*args, **kwargs)
        return wrapper
    return decorator
```

```python
#1.无参装饰器
def 装饰器(func)：
    @wraps(f)
    def wrapper(*args, **kwargs):
        #逻辑(只能判断一个写死的角色状态，没有传参)
        return func()
    return wrapper


#2.带参数装饰器（两层嵌套）

def 外层工厂(自定义参数)：#手动传入：角色列表，阈值等
    def 真正的装饰器(func)：
    @wraps(f)
        def wrapper(*args, **kwargs):
            #逻辑(只能判断一个写死的角色状态，没有传参)
            return func()
        return wrapper
    return 真正的装饰器
```

总结：

- 1.不用配置外部参数：直接用单层装饰器

- 2.想要额外自己传参数参与到控制逻辑：必须外层包一层函数来传参

### 5. bcrypt密码加密

1）盐值：特殊字符+字母+数字的组合

每次进行哈希的适合，把盐值加进去，同样为123456密码都不一样。哈希的加密方法用枚举倒退容易破解，简单密码很危险

```
1. 注册：明文密码 → bcrypt.hashpw(密码, bcrypt.gensalt()) → 哈希值（含盐）
2. 登录：用户输入密码 → bcrypt.checkpw(输入密码, 存储的哈希) → True/False
```

```python
from bcrypt import hashpw, gensalt, checkpw

def hash_password(password: str) -> str:
    """密码哈希"""
    pwd_bytes = password.encode("utf-8")[:72]   # bcrypt 最多 72 字节
    return hashpw(pwd_bytes, gensalt()).decode("utf-8")

def verify_password(plain: str, hashed: str) -> bool:
    """校验密码"""
    try:
        return checkpw(plain.encode("utf-8")[:72], hashed.encode("utf-8"))
    except (ValueError, TypeError):
        return False
```

### 3.Model层user.py

数据库里要存用户（用户名、密码、角色）。我们要用一个 Python 类描述"用户表长什么样"，并封装一些"查用户、建用户"的方法。这就是 Model 层的职责。

```python
   # ===== 类方法：封装数据操作（Model 层职责）=====

    @classmethod
    def find_by_username(cls, db: Session, username: str) -> Optional["User"]:
        """按用户名查用户（登录/注册查重用）"""
        return db.query(cls).filter(cls.username == username).first()
```

* `@classmethod`：装饰器，表示"这是个类方法"。普通方法第一个参数是 `self`（实例），类方法第一个参数是 `cls`（类本身）。
* 为什么用类方法？因为查用户不需要先有用户实例，直接用类调：`User.find_by_username(db, "admin")`。比"先 `user = User()` 再 `user.find(...)`"自然。是一种逻辑上的优化。

##### 4.2 密码哈希bcrypt：

哈希：把任意长度的输入，通过数学函数，变成固定长度的输出,单向、确定性,弊端：暴力破解，疯狂试、简单密码

bcrypt:破解起来很慢，并且自带盐值

#### 8.app/__init__.py—— 应用工厂

```python
"""Flask 应用入口：create_app 工厂 + 建表/建admin + 全局异常处理

【MVC 归属】基础设施层（应用工厂，串起 M/V/C 三层）
【思路】
1. _init_admin：建默认管理员 admin/admin123
2. create_app：创建 app → 注册蓝图 → 注册异常处理器 → 建表+建 admin

【和主项目的关系】本文件和主项目 app/__init__.py 同名同职责。
"""
from flask import Flask
from werkzeug.exceptions import HTTPException

from app.core.database import Base, engine, SessionLocal, close_db
from app.core.response import BizException, json
from app.core.security import hash_password


def _init_admin():
    """首次启动创建默认管理员 admin/admin123

    1. 开独立 session（不在请求上下文里，手动管）
    2. 查 admin 是否已存在；不存在才插入
    3. finally 关闭 session
    """
    # 函数内 import：避免模块加载时触发 app/models/__init__.py 整包加载
    from app.models.user import User
    db = SessionLocal()
    try:
        if not db.query(User).filter(User.username == "admin").first():
            db.add(User(username="admin", password_hash=hash_password("admin123"), role="admin"))
            db.commit()
    finally:
        db.close()


def create_app() -> Flask:
    """Flask 应用工厂：创建并配置 Flask app

    逐字思路：
    1. 创建 Flask app
    2. strict_slashes=False：/users 和 /users/ 都能匹配
    3. 注册业务蓝图（auth）
    4. 注册 teardown 钩子（请求结束自动关 DB 会话）
    5. 注册三级异常处理器（BizException → HTTPException → Exception 兜底）
    6. 在 app_context 里建表 + 建 admin
    """
    app = Flask(__name__)
    # strict_slashes=False：/api/v1/auth/users 和 /api/v1/auth/users/ 都能匹配
    app.url_map.strict_slashes = False

    # ===== 注册蓝图（Controller 层）=====
    from app.api.v1 import register_blueprints
    register_blueprints(app)

    # ===== 注册 teardown 钩子：请求结束自动关 DB 会话 =====
    app.teardown_appcontext(close_db)

    # ===== 三级全局异常处理（从具体到宽泛）=====
    # 优先级：BizException(业务) → HTTPException(框架HTTP) → Exception(兜底)

    @app.errorhandler(BizException)
    def handle_biz_exception(e: BizException):
        """业务异常 → 统一响应(携带具体业务码)"""
        return json(None, e.code, e.message, status=e.status_code)

    @app.errorhandler(HTTPException)
    def handle_http_exception(e: HTTPException):
        """框架级 HTTP 异常 → 业务码映射(401→1002, 403→1003, 404→2001)"""
        code_map = {401: 1002, 403: 1003, 404: 2001, 405: 1001}
        code = code_map.get(e.code, 5000)
        return json(None, code, str(e.description), status=e.code)

    @app.errorhandler(Exception)
    def handle_global_exception(e: Exception):
        """兜底异常 → 5000"""
        import traceback
        traceback.print_exc()  # 打印堆栈方便排查
        return json(None, 5000, f"服务器内部错误: {e}", status=500)

    # ===== 启动初始化：建表 + 建 admin =====
    with app.app_context():
        # 关键：必须 import 所有模型，Base.metadata 才能发现它们 → create_all 才能建表
        # 【坑】不能用 `import app.models`！会与局部变量 app(Flask实例) 冲突，
        #        把 app 重新绑定为模块，导致 return app 返回模块而非 Flask 实例
        import app.models as _models  # noqa: F401
        Base.metadata.create_all(bind=engine)
        _init_admin()

    return app
```
